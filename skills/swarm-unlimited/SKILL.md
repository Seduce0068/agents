## 目的

opencodeGO の無料モデル群のような無制限・高速モデルが使える間、あるいはユーザーが
明示的にコストを気にしないと宣言した場合に、swarm スキル群を上限を気にせず動かす。

ここでいう「無制限」は**同時起動数と深度の上限による抑制を行わない**という意味であり、
「必ず最大まで起動する」という意味ではない。何個起動するかは毎回親が判断する。
また、**トータル起動数（累計）の制限は元々定義されていない**。回数を数えて
自動停止するようなルールは設けない。

子エージェントのモデルは親が DSH のサブエージェント設定に登録されたモデルから選ぶ。
特定モデルを既定・推奨とせず、各モデルの特性（速度・能力・コンテキスト長・レート制限）を
実行時情報で確認し、タスクに合わせて判断する。一覧外のモデルは使わない。
選択理由は最終報告に記す。

リソース以外の安全境界は通常版と同じく厳密に守る。

## 呼び出し例

```text
@swarm-unlimited 対象スキル: swarm-coding / タスク: todo.md の未着手項目を消化
@swarm-unlimited 対象スキル: swarm-research / テーマ: Rust スクリプトツールの比較
@swarm-unlimited 対象スキル: swarm-project-review + swarm-todo-discovery / 同時実行
```

入力は対象スキル、そのスキルの入力、必要なら同時起動数と深度の希望値。
希望値は上限として扱い、親が実際の起動数を決める。

## 対象スキルと上書き範囲

| スキル | 上書きするセクション |
| --- | --- |
| `swarm-coding` | リソース予算、モデル切替の分岐（`coding` 種別を含む） |
| `swarm-todo-discovery` | リソース予算、モデル切替の分岐 |
| `swarm-project-review` | リソース予算、モデル切替の分岐 |
| `swarm-research` | リソース予算、モデル切替の分岐 |

起動時に対象スキルの `SKILL.md` を読み、上記セクションを本スキルの
「完全無制限プロファイル」で置き換えてから実行する。それ以外の手順・権限・
出力スキーマ・R6 集約は対象スキルに従う。

## 完全無制限プロファイル

| 項目 | 設定 |
| --- | --- |
| 同時起動数の上限 | 現状 80（環境の能力値）。親が必要な数を決め、上限まで使う義務はない |
| 子のネスト深度 | 現状 80（環境の能力値）。親が決定し、最大まで使う義務はない |
| トータル起動数 | 制限なし（定義されていない）。回数による自動停止は行わない |
| 段階的開始 | 親が判断。上限を気にせず必要な数から起動してよいが、最大構成を強制しない |
| ラウンド間コンパクション | 親がコンテキスト枯渇を避けるため必要最小限だけ行う |
| 出力件数上限 | 子 1 担当あたり 10 件は維持（起動数制限ではなく集約設計のため） |
| モデル切替 | 行わない。キャンペーン終了・他モデル登場・他プロバイダ移行でもプロファイルを下げない |
| 課金通知 | 従量モデルでの実行が判明した場合、ユーザーに通知するが自動停止しない |

「80」は現時点の環境の処理能力を示す値であり目標ではない。親が同時起動数と深度を決定する。
総数（累計の起動回数）と深度（委譲の階層数）は別項目であり混同しない。
実際の `maxTotalAgents` / `maxDepth` の値は環境依存のため、実行時に明示して報告する。
未確認なら「未確認」と記す。

### トータル制限がないことの扱い

- トータル起動数には制限がない。したがって「合計 N 回で停止」のようなルールは設けない。
- 終了はゴール完了、タスク枯渇、親の判断、またはハーネスの例外
  （コンテキスト枯渇、cap 超過、子セッションの大量失敗）による。
- 同時起動数と深度の上限は環境の能力値として扱い、超えない範囲で親が数を決める。
- 上限いっぱいまで使うかどうかは、観点の独立性と集約コストを見て親が判断する。

### 課金とリスクの扱い

- 本スキルは追加の購入操作・外部課金操作を行わない。モデル利用による従量課金は
  ユーザーが「無制限で実行して」と明示した上で受け入れたものとして扱う。
- 従量モデルでの実行が判明したら、起動前に使用モデルと設定した上限をユーザーへ通知する。
  自動停止はしないが、通知後も続行するかはユーザーの判断に委ねる。
- 親のコンテキスト枯渇、ハーネスの cap 超過（fatal）、子セッション大量失敗が起きたら
  安全に停止し、理由を報告する。

## ゴール運用（/goal）

本スキルは `/goal` を実行する。対象スキルのゴール運用に従いつつ、objective に
「完全無制限プロファイル」であることを明記する。

1. 起動時に `get_goal` で既存ゴールを確認し、同一目的がなければ `create_goal` で
   objective を設定する。`max_goal_rounds` は明示せず、deployment のデフォルト（現在 5000）を使う。
   ユーザーが明示的に数値を求めた場合のみ例外。
2. 対象スキルが `swarm-coding` の連続実行ループの場合、イテレーションごとに
   `/goal` を再度実行し、新規ゴールを作成する。
3. R6 で成果物確定・検証後に `update_goal` の `complete` で完了する。
4. `edit` / `pause` / `resume` はユーザーの直接指示がある場合のみ行う。

objective の例:

```text
対象スキル {skill} を完全無制限プロファイル（同時起動上限 {n} / 深度 {d}）で実行し、
タスク {task} の R1〜R6 を完了して成果物 {output} を確定する
```

## 起動手順

1. 対象スキルを特定し、その `SKILL.md` を読む。
2. リソース予算とモデル切替の分岐を本スキルの完全無制限プロファイルで上書きする。
3. 使用モデルと設定した上限をユーザーへ通知する（従量モデルの場合は特に明示）。
4. 対象スキルの R1 から実行する。起動数は親が判断し、上限まで使う必要はない。
5. R6 で対象スキルの集約・検証を行い、成果物を確定する。
6. 最終報告に次を含める: 使用モデル、実際の同時起動数とその上限、深度、
   トータル起動数（参考値。制限なし）、停止理由、完了したタスク、未解決点。

## 権限と安全境界

リソース以外は通常版より緩めない。

- 子: 対象スキルが定めた権限のみ（`review` / `investigate` / `research` / `ux` は読み取り専用、
  `dogfood` はユーザー承認済みの検証コマンドのみ実行可、
  `coding` / `design` は担当パス内のみ書き込み）。
- 破壊的操作（force push、履歴改変、タグの付け替え）、外部送信、グローバル設定変更は
  事前にユーザー確認を得る。
- 秘密情報（トークン、鍵、`.env`、非公開コード）をプロンプトやファイルに含めない。
- コミット前に秘密スキャン（Betterleaks 等）を実行する。導入済みなら pre-commit を主軸とし、
  CI スキャンを最終ゲートとして併設する。単独の pre-push 運用は避ける。
- 子間通信は行わず、結果は親にのみ返す。子の報告は仮説として扱い、
  親の Runtime Proof を優先する。
- 子セッションの失敗・途中終了を無視しない。未検証項目はその旨を明示する。
