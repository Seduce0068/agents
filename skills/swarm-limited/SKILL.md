## 目的

`swarm-unlimited` が上限による抑制を行わないのに対し、本スキルは**同時起動数と深度**に
明示的な上限を設ける。クオータ消費モデルや他無料プロバイダのレート制限に対応する。

誤解しないための原則:

- 上限は**同時に起動してよい数**の制限であり、**必ずその数まで使う義務はない**。
  何個起動するかは毎回親が判断する。
- **トータル起動数（累計）の制限は定義されていない**。回数を数えて
  自動停止するようなルールは設けない。
- 深度も同様に上限であり、最大まで使う義務はない。

リソース以外の安全境界は `swarm-unlimited` と同じく厳密に守る。

## 呼び出し例

```text
@swarm-limited 対象スキル: swarm-coding / タスク: todo.md の先頭3件 / 同時上限: 5・深度: 1
@swarm-limited 対象スキル: swarm-research / テーマ: 依存の代替候補
@swarm-limited 対象スキル: swarm-project-review + swarm-todo-discovery / 同時実行・制限付き
```

入力は対象スキル、そのスキルの入力、必要なら同時起動数と深度の希望値。
希望値は上限として扱い、実際の起動数は親が決める。

## 対象スキルと上書き範囲

| スキル | 上書きするセクション |
| --- | --- |
| `swarm-coding` | リソース予算、モデル切替の分岐（`coding` 種別を含む）、連続実行のイテレーション上限 |
| `swarm-todo-discovery` | リソース予算、モデル切替の分岐 |
| `swarm-project-review` | リソース予算、モデル切替の分岐 |
| `swarm-research` | リソース予算、モデル切替の分岐 |

起動時に対象スキルの `SKILL.md` を読み、上記セクションを本スキルの
「制限プロファイル」で置き換えてから実行する。それ以外の手順・権限・
出力スキーマ・R6 集約は対象スキルに従う。

## 制限プロファイル

| 項目 | 既定値 | 備考 |
| --- | --- | --- |
| 同時起動数の上限 | 5〜8 | 上限 12。ユーザー指定で下げられる。上限まで使う義務はない |
| 子のネスト深度 | 1 | 上限 1。深い委譲は行わない。最大まで使う義務はない |
| トータル起動数 | 制限なし（定義されていない） | 回数による自動停止は行わない |
| 段階的開始 | 親が判断 | 上限内で必要な数から始める。最大構成を強制しない |
| ラウンド間コンパクション | 親が判断 | 集約負荷を見て上位 5 件程度に圧縮して渡す |
| 1 担当の出力件数 | 5 件 | 起動数制限ではなく集約設計のための目安 |
| R4 のレビュアー数 | 1〜2 | 高リスク差分を重点レビュー |
| モデル切替 | 常にセーブ | 無制限キャンペーン中でもこの上限を維持する |

上限はすべて親が厳守する。環境の能力値（例: 同時 80・深度 80）が大きくても、
本スキルではその上限を下げる。「上限は能力値であり目標ではない」の原則を適用する。
ただし**上限に達していなくても、必要がなければ起動数を増やさない**。

### 上限の扱い

- 同時起動数と深度の上限は超えない。ただし上限まで使う義務はない。
- トータル起動数の制限はない。したがって「合計 N 回で停止」のようなルールは設けない。
- 終了はゴール完了、タスク枯渇、親の判断、またはハーネスの例外による。
- 上限を超える指定がユーザーからあった場合は、拒否理由を添えて既定の上限を適用する。
- `blocked` は安易に申請しない。Workspace の `AGENTS.md`「ゴール運用」に従う。

### モデルとコスト

- 従量モデル、他無料プロバイダのレート制限を前提とする。
- 子エージェントのモデルは親が DSH のサブエージェント設定に登録されたモデルから選ぶ。
  特定モデルを既定・推奨とせず、各モデルの特性（速度・能力・コンテキスト長・レート制限）
  と担当タスクを照らして判断する。一覧外のモデルは使わない。
- 選択前にレジストリ `~/.agents/references/model-registry/index.md` を読み、
  active のスナップショットを確認する。未記録・鮮度切れ・429 発生時は調査して更新し、
  archived モデルは選ばない。
- 起動前に使用モデル、同時起動数の上限、深度、当期の起動数（参考値）をユーザーへ通知する。
- 推定コストが不明なら「未確認」と記す。料金を断定しない。
- 無制限キャンペーン中でもプロファイルを上げない。上げたい場合は
  `swarm-unlimited` を明示的に使う。

## ゴール運用（/goal）

本スキルは `/goal` を実行する。対象スキルのゴール運用に従いつつ、objective に
「制限プロファイル」であることを明記する。

1. 起動時に `get_goal` で既存ゴールを確認し、同一目的がなければ `create_goal` で
   objective を設定する。`max_goal_rounds` は明示せず、deployment のデフォルト（現在 5000）を使う。
   ユーザーが明示的に数値を求めた場合のみ例外。
2. 対象スキルが `swarm-coding` の連続実行ループの場合、イテレーションごとに
   `/goal` を再度実行する。イテレーション回数の上限は設けない。
3. R6 で成果物確定・検証後に `update_goal` の `complete` で完了する。
4. 未完了項目が残る場合は `complete` せず、`## 進行中` に残す。
  これはトータル制限ではなく、ゴールの完了条件による。
5. `edit` / `pause` / `resume` はユーザーの直接指示がある場合のみ行う。

objective の例:

```text
対象スキル {skill} を制限プロファイル（同時起動上限 {n} / 深度 {d}）で実行し、
タスク {task} の R1〜R6 を上限内で完了して成果物 {output} を確定する
```

## 起動手順

1. 対象スキルを特定し、その `SKILL.md` を読む。
2. リソース予算とモデル切替の分岐を本スキルの制限プロファイルで上書きする。
3. 使用モデルと設定した上限をユーザーへ通知する。
4. 対象スキルの R1 から実行する。起動数は親が判断し、上限まで使う必要はない。
5. 各ラウンド開始前に**同時起動数の上限**を超えないか判定する（トータル制限はない）。
6. R6 で対象スキルの集約・検証を行い、成果物を確定する。
7. 最終報告に次を含める: 使用モデル、実際の同時起動数とその上限、深度、
   トータル起動数（参考値。制限なし）、停止理由、完了したタスク、未解決点。

## 権限と安全境界

`swarm-unlimited` と同じく、リソース以外は緩めない。

- 子: 対象スキルが定めた権限のみ（`review` / `investigate` / `research` / `ux` は読み取り専用、
  `dogfood` はユーザー承認済みの検証コマンドのみ実行可、
  `coding` / `design` は担当パス内のみ書き込み）。
- 破壊的操作（force push、履歴改変、タグの付け替え）、外部送信、グローバル設定変更は
  事前にユーザー確認を得る。
- 秘密情報（トークン、鍵、`.env`、非公開コード）をプロンプトやファイルに含めない。
- コミット前に秘密スキャン（Betterleaks 等）を実行する。導入済みなら pre-commit を主軸とし、
  CI スキャンを最終ゲートとして併設する。単独の pre-push 運用は避ける。
- 子間通信は行わず、結果は親にのみ返す。子の報告は仮説として扱い、
  親の Runtime Proof を優先する。
- 子セッションの失敗・途中終了を無視しない。未検証項目はその旨を明示する。
