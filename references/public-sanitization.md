## サニタイズ基準（2026-11-25 の監査で確立）

個人リポジトリを public にする前は、テキストだけでなく以下を全リポジトリ横断で確認する。未知の残存が出続けるため、目視とスキャナを併用し、新規検出がゼロになるまで繰り返す。

- **個人・アカウント識別子**: 現行/旧アカウント名、ローカルユーザー名、実メール、実名。テスト fixture の canary や著作権表記、スキル使用例の GUID/リソース名にも残り得る。プレースホルダは `<user>` / `TEST_USER` / `00000000-0000-...` / `example-rg` 等を使う。
- **内部ネットワーク**: tailnet ドメインとホストラベル、LAN/IPv6 プレフィックス、ルータ機種・回線事業者・プラン名、実 MAC、実 NIC 名。IPv6 は `2001:db8::/32`、IPv4 は `203.0.113.0/24` 等の RFC 予約レンジに置換する。
- **実機 finger print**: CPU/GPU/マザーボード/ストレージ型番、容量、カーネルビルド文字列、解像度・スケール、PID・時刻・ベンチ値。汎用表現（「汎用 GPU」「Kubuntu/Wayland」等）または丸めた参考値に置換する。
- **マシン固有パス import**: `import ... from "/home/..."` や `C:/Users/...` はパッケージ名 import へ変更し、対応する devDependency を追加する。
- **画像**: 上記 OCR 走査で検出された画像は削除し、`git filter-repo --path <file> --invert-paths` で履歴からも消去して force push する（実行前にユーザー確認）。削除後は参照 Markdown も更新する。
- **意図的な防御用パターン**: 公開ゲートの検出リストに含める特定文字列は「機微情報の残存」ではない。ただし「意図的プレースホルダ」と誤判定する前に必ず実ファイルを読み、実際に旧名が残っていないことを確認する（監査で誤検知として却下した箇所から後日実残存が見つかった事例あり）。

## コミット author とリモート履歴（2026-11-26 のセッションで確立）

- **公開リポジトリのコミット author 匿名化**: グローバル `git config user.name` / `user.email` に実名・実メールが設定されたままだと、push したコミットの author に個人情報が残る。公開リポジトリへコミットする際は `git -c user.name=<匿名名> -c user.email=<匿名>@users.noreply.github.com commit` で上書きする（今回は `dsh-agent` を使用）。恒久的なグローバル設定の匿名化はユーザー承認後に実施する。
- **リモート側の force update 検出時**: `git fetch` の結果、リモートが force update されていたら force push せずリモートを正とする。rebase / `git am` が多数競合する場合は無理に解消せず、自分の変更がリモート最新に既に含まれていないか確認し、重複コミットは破棄して不足分だけを再コミット・push する（ZenzaWatch で ahead 854 / behind 857 の分岐となり、競合多数のためこの手順を適用した事例あり）。
